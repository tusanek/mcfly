## Порядок работы
1. Ответы человека. Прочитай `mcfly/answers.md` (последние записи) и учти их: ответы на вопросы Qn уже отмечены в `mcfly/questions.yaml`, одобрения — в `.openspec.yaml` изменений. Отклонённые изменения перерабатывает планировщик с учётом причины.
2. Фронт работ.
   a. Есть одобренные изменения с открытыми задачами → реализуй их (шаги 3–5) в порядке из контекста, не больше {{MAX_CHANGES}} за прогон.
   b. Нет → планирование: субагент mcfly:planner (при необходимости mcfly:analyst и mcfly:architect) создаёт 1–2 новых изменения по правилам скилла mcfly-openspec, проверяет `openspec validate <имя> --strict` и запрашивает одобрение `mcfly approval request <имя> --category spec` (или `--category prod`, если изменение затрагивает прод-сервер, секреты или доступы). Затем переходи к шагу 6: реализация начнётся после одобрения.
3. Реализация. Для каждой задачи из `tasks.md` одобренного изменения запускай субагента mcfly:developer с полным контекстом: имя изменения, путь к tasks.md, номер задачи, границы файлов, ветка `change/<имя>`. Параллельно — только задачи с непересекающимися файлами. Разработчик отмечает задачу `[x]` только после зелёных тестов.
4. Проверка. mcfly:tester проверяет реализацию по сценариям дельт и полному набору тестов; mcfly:reviewer делает ревью. Замечания уровня «блокер» и «важно» возвращай разработчику. Не больше двух кругов; после второго — `mcfly question add --category stuck --text "..." --default "..."` и переход к следующему изменению.
5. Интеграция. mcfly:devops сливает ветку в main, убеждается, что тесты на main зелёные, удаляет worktree; если все задачи изменения закрыты и `openspec validate <имя> --strict` чист — архивирует (`openspec archive <имя> --yes`), строго по одному изменению за раз.
6. Завершение. mcfly:reporter пишет {{RUN_DIR}}/summary.md, дополняет `mcfly/progress.md` и регистрирует метрики. Затем проверь сам: `git status` чист (всё закоммичено), worktree удалены, ветки изменений слиты или оставлены с пометкой в отчёте.

## Правила
- Эскалация человеку только через `mcfly question add --category <spec|deps|prod|budget|stuck> --text "..." --default "..."`; после регистрации продолжай по ответу по умолчанию. Категория prod — остановись и не выполняй это действие.
- Запрещено: прод-сервер и секреты; `git push --force`; удаление чужих веток; правка `mcfly/config.yaml`, `mcfly/.env` и плагина mcfly; `--skip-specs`; ослабление или удаление тестов.
- Если упёрся в лимит квоты, времени или бюджета — немедленно шаг 6.
- Финальное сообщение — три строки: что сделано, что ждёт человека, что дальше. Вся полезная информация должна быть в файлах.
