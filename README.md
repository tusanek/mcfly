# mcfly

Комплект «ИИ-команды разработки» на нативном Claude Code. Ставится на любой проект и работает без человека за клавиатурой: ночью команда агентов планирует, пишет код через TDD, проверяет, ревьюит и интегрирует, а утром вы читаете сводку в Telegram и отвечаете на вопросы с телефона.

**Что внутри**

- Плагин Claude Code: одиннадцать ролей-субагентов (lead, analyst, architect, planner, developer, tester, reviewer, devops, designer, user, reporter), скиллы процесса, слэш-команды, хук контекста.
- CLI `mcfly`: ночные прогоны по расписанию launchd (macOS), проверка окна запуска, лимит времени, `caffeinate`, разбор результата, метрики.
- Спецификации на [OpenSpec](https://github.com/Fission-AI/OpenSpec): изменение = proposal + дельты спецификаций + design + tasks. mcfly добавляет флаг одобрения человеком.
- Telegram в обе стороны: утренняя сводка, вопросы с ответом по умолчанию и сроком, одобрения изменений; ответы пишутся в файлы проекта, команда читает их на следующем прогоне.

## Требования

- macOS (launchd, caffeinate), Node ≥ 20, git.
- Claude Code CLI 2.1+ с подпиской (прогон идёт через `claude -p`, agent teams не используются).
- OpenSpec: `npm install -g @fission-ai/openspec@latest`.
- Бот Telegram (создаётся в BotFather).

## Установка

```bash
git clone https://github.com/tusanek/mcfly.git ~/mcfly
cd ~/mcfly && npm install && npm link   # даёт команду mcfly в PATH
```

Если у вас настроен SSH-ключ для GitHub, можно клонировать и так: `git clone git@github.com:tusanek/mcfly.git ~/mcfly`.

Быстрый старт по шагам: [docs/quickstart.md](docs/quickstart.md).

Обновление до свежей версии: `cd ~/mcfly && git pull && npm install`. Что изменилось — в [CHANGELOG.md](CHANGELOG.md).

## Для команды

mcfly ставится каждому участнику отдельно: он работает на своём Mac и со своими доступами. Общего сервера нет.

Что нужно каждому:

- **Свой Mac.** Ночные прогоны запускает launchd (служба macOS для заданий по расписанию), поэтому на Linux и Windows они не работают.
- **Своя подписка на Claude Code.** Прогон идёт от имени того, кто его запустил, и расходует его лимиты.
- **Свой бот в Telegram.** Создаётся в BotFather за пару минут. Один бот на двоих не делите: ответы и одобрения перепутаются.
- **Свой файл `mcfly/.env` с токеном бота.** Он в `.gitignore` и в git не попадает. Токены никому не пересылайте и не коммитьте.

Если mcfly нужно поставить на общий проект команды, `mcfly init` выполняет один человек. Остальные получают `mcfly/config.yaml`, правила и спецификации вместе с репозиторием проекта. Ночные прогоны на одном проекте лучше держать у одного участника: два параллельных прогона будут править одни и те же ветки.

Нашли ошибку или есть идея — заведите задачу (issue) в репозитории на GitHub. Если хотите вносить правки сами, попросите владельца добавить вас соавтором (collaborator) или пришлите запрос на слияние (pull request) из своей копии (fork).

## Удобство интерфейса

С 0.10.0 команда следит за удобством, если в проекте есть описание продукта `mcfly/product.md` (что это, для кого, какую боль снимает, правила, которые нельзя нарушать; шаблон кладёт `mcfly init`, файл ведёте вы):

- описание продукта и цели `mcfly/goals.md` получает каждый агент в начале прогона;
- план, который меняет видимое, содержит раздел «Как это будет выглядеть»; под ним в боте кнопка «👀 Как будет выглядеть» — образцы приходят настоящими сообщениями с ненастоящими кнопками;
- готовое изменение после тестировщика проходит роль «пользователь»: неудобное возвращается разработчику или попадает в список предложений;
- сообщение боту «неудобно: текст» — жалоба, которой команда займётся раньше новых функций;
- `worktree.shared` в `mcfly/config.yaml` — папки зависимостей, которых нет в git (например `[miniapp/node_modules]`). Claude Code создаёт worktree разработчика без них; зависимости ставятся один раз в основном каталоге, а разработчик подключает их ссылками командой `mcfly worktree link`. Папки `node_modules`, `.venv` и `venv` основного каталога, которых нет в списке, `mcfly doctor` и `mcfly worktree link` называют: в worktree их не будет.
- `design.skills` в `mcfly/config.yaml` — навыки Claude Code для задач с интерфейсом (например `[impeccable]`); ставите их вы, `mcfly doctor` проверяет наличие.

Без `mcfly/product.md` всё работает как раньше.

## Устройство репозитория

- `agents/` роли, `skills/` навыки, `commands/` слэш-команды, `hooks/` хук контекста, `prompts/run.md` промпт прогона.
- `src/` код CLI, `test/` тесты (`npm test`).
- `templates/` файлы, которые `mcfly init` кладёт в проект.
- `docs/quickstart.md` быстрый старт, `docs/superpowers/` планы и проекты доработок.

## Команды

| Команда | Что делает |
|---|---|
| `mcfly init [--name <проект>] [--with-tracker]` | Создаёт `mcfly/` в проекте, правила в `.claude/settings.json`, раздел в CLAUDE.md, инициализирует OpenSpec |
| `mcfly doctor` | Проверяет окружение и настройки |
| `mcfly run [--mode night\|day] [--dry-run]` | Прогон команды. `night` запускается только в окне слота, иначе фиксирует пропуск |
| `mcfly summary [--send]` | Утренняя сводка: в консоль или в Telegram. В Telegram — простыми словами, без технических данных; в консоли после сводки печатается технический хвост: стоимость, ходы, субагенты, метрики, разделы «Сделано» отчётов (0.9.0) |
| `mcfly summary --weekly [--send]` | Недельная сводка (0.13.0): итоги семи дней; `--send` — отправить в Telegram. По расписанию — `schedule.weekly_day` и `schedule.weekly_at` |
| `mcfly video setup` / `mcfly video build [--weekly] [--director off\|on\|review] [--send]` | Сводка роликом с голосом (0.12.0): установить сборщик и озвучку; собрать ролик из текущей сводки (`--weekly` — из недельной, `--director` — кто пишет сценарий), `--send` — отправить в Telegram. См. «Сводка роликом» |
| `mcfly answers [--once]` | Забирает ответы из Telegram и применяет их сразу по приходу (постоянное задание launchd: цикл длинного опроса по `answers_every_minutes` минут); `--once` — один раз |
| `mcfly context` | Контекст состояния для агентов (его же подмешивает хук SessionStart) |
| `mcfly status` | Состояние проекта |
| `mcfly question add --category <c> --text <t> --default <d>` | Эскалация человеку (используют агенты) |
| `mcfly approval request\|set\|list` | Одобрения изменений OpenSpec |
| `mcfly approval pause <изменение> --until <ГГГГ-ММ-ДД> [--note <t>]` / `approval resume <изменение>` | Отложить одобренное изменение до даты: команда его не берёт, сводка показывает «⏸ отложено до» (только человек) |
| `mcfly metric add --key <k> [--value <n>]` | Метрики (используют агенты) |
| `mcfly shift start <изменение>\|merge\|write [--file]\|auto` | Передача смены: дневная ветка `shift/<изменение>-…`, слияние в `change/<изменение>`, запись передачи, авто-передача |
| `mcfly telegram pair` | Привязка чата |
| `mcfly schedule install\|remove\|status` | Задания launchd (служба macOS, запускающая программы по расписанию): прогоны, сводка и постоянный опрос Telegram `answers`. `install` переустанавливает их и выходит с кодом 1, если какое-то задание не поднялось; `status` по каждому заданию из конфигурации пишет ✓ (загружено, номер процесса) или ✗ «НЕ загружено» и выходит с кодом 1, если что-то не загружено |
| `mcfly finding add --text <t> [--evidence <t>]` / `finding list` / `finding send\|drop <Fн>` | Находки для доработки самого mcfly: записывают агенты и сессии, передаёт в общий ящик или убирает владелец (в боте — кнопками, `send` и `drop` — только в его терминале) |
| `mcfly samples template` | Шаблон «чат Telegram» для картинок образцов сообщений бота → `design/samples/telegram-chat.html` |
| `mcfly worktree link [--project <каталог>]` | В worktree команды: ссылки на общие папки основного каталога из `worktree.shared` (например `miniapp/node_modules`), спрятанные от git через `.git/info/exclude`; разработчик запускает первым шагом |
| `mcfly remind list\|rm <Rн>` | Напоминания владельцу: список и отмена (ставятся в боте: «напомни 19:00 текст»); в прогоне команды `rm` запрещён |
| `mcfly action list\|run <id> [--yes]` | Действия владельца из раздела `actions` (выкат, откат, eval…): список и запуск из терминала с итогом и в Telegram. `prepare`/`exec` — служебные, их запускает бот |

Общий флаг `--project <dir>`; по умолчанию текущий каталог или `MCFLY_PROJECT_DIR`. Из связанного git worktree (например, сессии `.claude/worktrees/<имя>`) команды работают с основным деревом проекта и пишут в stderr, с каким каталогом работают (0.7.12); исключения — `init` и `shift`.

## Цикл прогона

1. Runner забирает ответы из Telegram, закрывает просроченные вопросы ответами по умолчанию, авто-одобряет просроченные изменения (кроме категории prod), собирает контекст (изменения с прогрессом по веткам `change/*`, worktree команды, вопросы, ответы, журнал) и запускает `claude -p --agent mcfly:lead` с промптом из `prompts/run.md`. Фоновые задачи в прогоне отключены (`CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1`): субагенты работают синхронно, параллельность — несколько вызовов в одном ходе лида. Токен Telegram агентам не передаётся.
2. Лид смотрит фронт работ: есть одобренные изменения с открытыми задачами → реализация; нет → планировщик создаёт 1–2 изменения и запрашивает одобрение.
3. Разработчики берут по задаче, каждый в worktree, который создаёт Claude Code от main (`worktree-agent-<id>`): сливают в него `change/<имя>` (`git merge --ff-only`), дальше красный тест → зелёный → коммит → `[x]` в tasks.md; лид переносит результат в ветку изменения `git fetch . worktree-agent-<id>:change/<имя>`. Схема — раздел «Рабочие копии и ветки» навыка mcfly-process. Тестировщик проверяет по сценариям дельт, ревьюер делает ревью (не больше двух кругов).
4. DevOps сливает в main, гоняет тесты, архивирует изменение через `openspec archive`, строго по одному.
5. Репортёр готовит текст `runs/<id>/summary.md` и строки журнала и регистрирует метрики; файлы записывает и коммитит лид (Claude Code не даёт субагентам писать файлы отчётов). Runner проверяет `openspec validate --all --strict` (отложенные изменения ошибкой не считаются), незакоммиченные файлы (без своих служебных) и worktree команды с незакоммиченной работой, записывает результат, пишет авто-сводку, если репортёр не отработал, и коммитит только свои служебные пути.

## Передача смены

Днём человек работает с Claude, ночью команда продолжает без него.
- **Утро** — навык `/mcfly:take-shift` («прими смену»): читает ночную передачу `mcfly/shifts/*-night.md`, сверяет с ветками и прогонами, предлагает план дня. Для совместной работы над изменением — `mcfly shift start <изменение>` в worktree сессии.
- **Вечер** — навык `/mcfly:hand-shift` («сдай смену»): `mcfly shift merge` вливает дневную ветку в `change/<изменение>` (только fast-forward; конфликт или грязный worktree команды — отказ), затем `mcfly shift write` записывает передачу, коммитит только её и шлёт строку в Telegram.
- **Ночь без сдачи** — runner перед прогоном собирает авто-передачу по веткам и worktree; несданные ветки `shift/*` помечены «не трогать». Передача — первый блок контекста лида, действует в рамках одобренного.
- **Конец ночи** — репортёр последнего слота готовит `-night.md`, лид записывает; не дошёл до отчёта — runner собирает её сам. Сводка показывает «Предложение на день».

## Эскалации и одобрения

Категории: `spec` (спецификация, критерии приёмки), `deps` (зависимости, платные ресурсы), `prod` (прод-сервер, секреты, доступы), `budget`, `stuck` (два неудачных подхода). Каждый вопрос приходит с ответом по умолчанию и сроком (24 ч); после срока команда действует по умолчанию. Категория `prod` по умолчанию не исполняется никогда, вопрос без ответа по умолчанию допустим только в ней. Предложения изменений: молчание 24 ч = одобрение (кроме prod и неизвестных категорий). Одобрение ставит только человек: в прогоне команды `mcfly approval set` отклоняется, агенты используют `approval request`. Решение человека `approval set` сразу коммитится отдельным коммитом (`chore(<изменение>): одобрение человека — <статус>`), только файл `.openspec.yaml` изменения; если коммит не удался (изменение ещё не в git), метаданные закоммитит ближайший прогон. Это защита от ошибки агента, а не от злого умысла: обойти её можно, убрав `MCFLY_RUN_ID` из окружения или правя `.openspec.yaml` вручную.

Форматы ответов в Telegram:

```
Q3: b                      ответ на вопрос Q3
Q3 свой текст              то же
approve add-cache          одобрить изменение
reject add-cache причина   отклонить
запусти                    прогон (если ничего не идёт; нет работы и ждёт одобрение — не запускается)
запусти всё равно          прогон, даже если работы нет
запусти 3                  прогон, в котором команда возьмёт не больше трёх изменений
очередь                    что команда делает и планирует и в каком порядке; кнопки «⬆ Вперёд»
вперёд I7                  поставить взятый пункт или изменение первым в очереди
закрыть I7                 закрыть без работы пункт или план, который делать не нужно
вернуть имя-изменения      отменить сделанное без вашего одобрения: ближайший прогон вернёт как было
статус  (/status)          обзор: ссылки (links), прогон, изменения, вопросы, что нужно от вас, следующий прогон, квота; «где мы» — то же;
                           следом — «🗳 Ждут вашего решения» с кнопками одобрить/отклонить изменение и ответа по умолчанию (если есть что решать)
цели  (/goals)             цель, веха и чек-лист «сделано N из M» из mcfly/goals.md
предложения  (/ideas)      что команда может сделать дальше: ваш бэклог и идеи команды; кнопки «✅ Берём» / «⏸ Не сейчас»
идея: текст                своя идея в список предложений
статистика  (/stats)       прогоны, задачи, изменения, возвраты с ревью, расход за 7 дней и всего
последний прогон  (/last)  «Простыми словами», «Сделано», «Нужно от вас» последнего отчёта
помощь  (/help)            все команды с примерами
действия  (/actions)       действия владельца кнопками (раздел actions), каждое с подтверждением
ответ свайпом на вопрос    ответ на этот вопрос (если в сообщении один открытый вопрос)
любой другой текст         заметка для команды
```

Команды обзора только читают состояние проекта и отвечают сразу. Они же — в меню «/» бота и на постоянной клавиатуре внизу чата («📍 Статус», «🎯 Цели», «📊 Статистика», «▶️ Запусти», «💡 Предложения»); меню и клавиатуру задание `answers` ставит само при первом цикле новой версии.

Ссылки проекта (сайт, стенд, дашборд) показываются в «статус» строкой 🔗 под заголовком — раздел `links` в `mcfly/config.yaml`:

```yaml
links:
  Сайт: "http://10.0.0.1:8080/latest/"
```

## Действия владельца в Telegram

С 0.6.0 владелец может делать из бота то, что раньше запускал скриптом в терминале: выкат, откат, приёмочный eval, проверку сервера, чистку. Действия задаёт только владелец в разделе `actions` файла `mcfly/config.yaml` (команде правка этого файла запрещена, поэтому подсунуть кнопке свою команду она не может):

```yaml
actions:
  deploy:
    title: "🚀 Выкатить"
    describe: "jar из main с тестами → сервер → пересборка сайта → бот на Mac"
    prepare: "bash ~/deploy/deploy.sh --plan"   # необязательно: вывод показывается перед «Да»; отказ — код ≠ 0 и причина строкой «@@ »
    run: "bash ~/deploy/deploy.sh"
    offer: "bash ~/deploy/deploy.sh --needed"   # код 0 → кнопка в «статус»
    followups: [rollback]                       # кнопки под итогом
    timeout_minutes: 45                         # по умолчанию 60
    confirm: true                               # false — без подтверждения (только чтение)
    during_run: false                           # по умолчанию во время прогона команды не запускается
    vpn: true                                   # поднять VPN (run.vpn_service) до запуска
  eval:
    title: "🧪 Eval промптов"
    run: "bash ~/deploy/eval.sh"
    after: deploy                               # 0.8.2: сначала deploy — его offer вернул 0 → предупреждение перед «Да»
```

`after` (с 0.8.2) — действие, которое нужно сделать раньше этого, например eval после выката (у того действия должен быть `offer`). Перед «Да» бот выполняет `offer` того действия; код 0 — значит, оно сейчас нужно: сверху подтверждения строка «⚠️ Похоже, сначала нужно «🚀 Выкатить»… Без этого «🧪 Eval промптов» сработает на прежней версии», под кнопками «Да» и «Отмена» — кнопка того действия. Запуск не запрещается: решает владелец. Агенты в контексте видят «только после «🚀 Выкатить»» и в «Нужно от человека» ставят кнопки в этом порядке. После добавления `after` раздел нужно заново подтвердить: `mcfly action trust`.

Как это выглядит: «🛠 Действия» (кнопка внизу чата, `/actions`) → кнопка действия → сообщение «Что будет сделано» и вывод `prepare` (как и итог — строки `@@ `, а без них последние 20 строк) → «✅ Да, выполнить» (если `prepare` завершилась с кодом не 0 и вывела строки `@@ ` — это отказ с причиной: «⏹ Подготовка остановила действие» и эти строки, без «Да»; без строк `@@ ` — «❌ Подготовка не удалась») → действие идёт отдельным процессом (`mcfly action exec`), опрос Telegram не ждёт → итог: ✅/❌/⏱, длительность, строки скрипта с префиксом `@@ ` (если их нет — последние 20 строк), кнопки `followups`. «Да» несёт одноразовый код, который живёт 30 минут: старое или повторное нажатие ничего не запустит. Одновременно идёт одно действие (`mcfly/logs/.action.lock`); во время прогона команды действия с `during_run: false` не запускаются. Полный вывод — `mcfly/logs/actions/<время>-<id>.log`, запуск — запись `type: action` в `metrics.jsonl`; не дошедший итог дошлёт задание `answers` (сообщение, которое Telegram отклонил как Bad Request, из очереди выбрасывается с записью в журнал, чтобы не держать остальные). В «статус» — идущее действие и кнопки действий, у которых `offer` вернул 0 (за 10 секунд). Агенты видят список действий в контексте и в «Нужно от человека» ссылаются на кнопку; в прогоне команды `mcfly action` отклоняется (`MCFLY_RUN_ID`).

Защита (от ошибки агента, не от злого умысла): раздел `actions` работает, только если владелец подтвердил его текст командой `mcfly action trust` в своём терминале (нужен живой терминал; подтверждение хранится вне проекта, `~/.config/mcfly/trusted-actions.json`). Подтверждается и содержимое файлов, на которые ссылаются команды, вместе с остальными файлами их каталогов (без подкаталогов, где обычно лежит состояние скриптов). Любая правка раздела или этих скриптов выключает кнопки, `offer` и `prepare` до нового подтверждения; `mcfly doctor` это показывает. Код «Да» привязан к тексту раздела: команду поправили после показа «что будет сделано» — код не сработает. Процесс действия получает от бота одноразовый пропуск (2 минуты): `mcfly action exec|prepare` без него отклоняется с сообщением в чат, а `mcfly action run` работает только в терминале. Действия принимаются только от владельца: `telegram.owner_id`, а без него — от собеседника личного чата `chat_id`; в групповом чате без `owner_id` действия выключены. Проверки `offer` выполняются только на «статус» владельца. `mcfly action run` в терминале тоже требует подтверждённого раздела. Меню и объявление о действиях обновляются, только когда раздел подтверждён. Скрипты работают с окружением launchd: пути, Java и ключи в них задаются явно.

## Напоминания в Telegram

С 0.8.0 бот напоминает владельцу о деле в заданное время — в тот же чат, где кнопки. Пример: «напомни 19:00 нажать 🧪 Eval промптов» (eval днём съедает общую квоту LiteLLM, вечером — нет).

- Поставить — сообщением боту: `напомни 19:00 текст` (сегодня; если 19:00 уже прошло — завтра), `напомни завтра 10:00 …`, `напомни послезавтра 10:00 …`, `напомни 08.11 10:00 …` (дата без года, если прошла, — в следующем году), `напомни через 2 ч …`, `через 30 мин`, `через час`. Время — по часам Mac. Бот отвечает «🔔 R3: напомню сегодня в 19:00 — …»; непонятное время — подсказка с примерами.
- Приходит «🔔 Напоминание R3: …». Под ним — кнопки действий из раздела `actions`, названных в тексте (по названию кнопки без эмодзи, например «Eval промптов»): нажатие ведёт к обычному «что будет сделано» и «✅ Да», само напоминание ничего не запускает. Рядом «⏰ Через час» — то же напоминание через час.
- Посмотреть и отменить: «напоминания» или `/reminders` — ожидающие по сроку с кнопкой «✖️ Отменить» у каждого; в терминале `mcfly remind list`, `mcfly remind rm R3`.

Как устроено: напоминания лежат в `mcfly/logs/reminders.json` (вне git, переживают перезапуск; правка — под короткой блокировкой файла, запись атомарная). Срок проверяет задание `answers` на каждом круге длинного опроса (до ~25 с) — отдельного демона нет. Mac спал или не было связи — после пробуждения напоминание придёт с пометкой «🕓 Опоздало на 2 ч 10 мин (срок был 19:00)» (опоздание меньше 5 минут не помечается). Каждое приходит один раз: отправленным оно считается только после того, как Telegram принял сообщение; при сбое связи остаётся ожидающим и уходит на следующем круге, а отклонённое Telegram (Bad Request) помечается и не держит остальные. В `answers.md` напоминания не пишутся — команде они не нужны. Отправленные и отменённые старше 7 дней удаляются из файла; повреждённый файл не затирается — бот отвечает ошибкой, пока его не исправят или не удалят.

## Находки для доработки mcfly

С 0.11.0 проблемы самого mcfly (а не вашего проекта) собираются сами, а вы только решаете, передавать ли их дальше.

- Кто записывает: агенты прогона и сессии Claude Code — командой `mcfly finding add --text "что не так" --evidence "что видели"`; вы — сообщением любому боту команды: «mcfly: что не так». Ключи и токены в тексте скрываются; правило для агентов — без подробностей проекта.
- Как решаете: находки команды ждут вас. Под итогом прогона, сводкой и «Статусом» появляется кнопка «📮 Находки для mcfly (N)»; по ней или по слову «находки» — список с кнопками «📮 Передать» и «🚫 Не надо» у каждой и «Передать все». Ваше собственное сообщение «mcfly: …» одобрения не ждёт — уходит сразу.
- Куда уходит: переданное дописывается в общий ящик — файл `~/mcfly-inbox.md` (путь задаёт `findings.inbox`, один на все ваши проекты; только файл `.md` в домашнем каталоге: не в скрытой папке, не внутри проекта с `.git`, не файл правил вроде `CLAUDE.md` или `README.md`, не ссылка) под заголовком «дата · проект · версия mcfly». Сессия доработки mcfly читает ящик первым и отмечает взятое `[x]` с версией.
- Выключить: `findings.enabled: false` в `mcfly/config.yaml`.

Хранение — `mcfly/findings.yaml` (в git, коммитит прогон). Передать или убрать находку может только владелец: кнопкой в боте или `mcfly finding send|drop <Fн>` в своём терминале; в прогоне и без живого терминала команда отказывает.

## Сводка роликом

С 0.12.0 утреннюю сводку можно получать ещё и коротким роликом с голосом: вертикальный, около минуты. Текст сводки приходит как раньше и первым; ролик собирается после него и приходит ответом на сводку — через 2–4 минуты, если сценарий пишет режиссёр, и примерно через полминуты, если его собирает код.

Что в ролике:
- что сделано — пересказы до трёх последних прогонов, на них уходит большая часть времени;
- как это выглядит — образцы из раздела «Как это будет выглядеть» описаний изменений, нарисованные экраном чата с сообщением и кнопками;
- дела, которые ждут вас вне бота: правка на ноутбуке или сервере, запуск скрипта. Одобрения, вопросы и выбор по спискам в ролик не идут — они в тексте сводки, с кнопками;
- прогоны — одной строкой на заставке; отдельной сценой и вслух — только если что-то не удалось;
- что команда делает дальше.

- Сценарий (0.15.0): по умолчанию его пишет роль-режиссёр, а роль «пользователь» один раз смотрит кадры как зритель и сверяет факты с данными (`video.director: review`). Ролик получается как короткое видео в соцсетях: зацепка, одна мысль на сцену, диктор говорит всё время показа. Режиссёр запускается отдельным обращением к Claude по вашей подписке после отправки текста; дешевле — `video.director: on` (без зрителя) или `off` (сцены собирает код). Сколько стоил ролик, видно в журнале задания и в `usage.json` рабочей папки режиссёра; зритель работает на лёгкой модели (`video.viewer_model`). Если режиссёр недоступен или не уложился в `video.director_minutes`, ролик всё равно придёт — из сцен кода. Что написал режиссёр и что заметил зритель, лежит в `~/.mcfly/video/work/<проект>/`.
- Установить, один раз на Mac: `mcfly video setup`. Ставит в `~/.mcfly/video` сборщик роликов [Remotion](https://www.remotion.dev) (около 700 МБ) и окружение локальной озвучки Silero с моделью голоса (около 1 ГБ; готовое окружение `~/.video-explainer` подхватывается). Нужны Node и `python3`. Одно окружение на все ваши проекты.
- Включить в проекте: `video.enabled: true` в `mcfly/config.yaml`. Проверка — `mcfly doctor`; проба без отправки — `mcfly video build` (печатает путь к ролику, длину, размер и кто писал сцены), с отправкой — `mcfly video build --send`.
- Голос — `video.voice` (aidar, baya, kseniya, eugene, xenia), скорость — `video.voice_speed` (1.1), примерная длина — `video.max_seconds`. Текст никуда не уходит: озвучка работает на вашем Mac.
- Произношение: синтезатор читает только русские буквы, поэтому числа, время и даты mcfly пишет словами сам. Иностранные слова диктор пропускает (они есть на экране), кроме тех, что в словаре. Своё слово и ударение добавьте в `video.pronounce`, например `myapp: "май +апп"` («+» перед ударной гласной). Название проекта латиницей стоит вписать туда же — иначе диктор его не назовёт.
- Если ролик не собрался (нет окружения, не уложился в `video.timeout_minutes`, Telegram не принял файл), сводка от этого не страдает: в чат придёт одна строка с причиной, не чаще раза в сутки.
- Лицензия Remotion: бесплатно для частных лиц, некоммерческих организаций и компаний до трёх сотрудников; компаниям крупнее нужна платная лицензия Remotion.

## Недельная сводка

С 0.13.0 раз в неделю (по умолчанию в воскресенье в 19:00) в Telegram приходят итоги семи дней: какие изменения завершены и сколько задач закрыто, что в работе, продвижение по целям («сделано N из M» и прирост за неделю), прогоны по исходам, что ждёт вашего решения и сколько занято недельного лимита подписки. Если включён ролик (`video.enabled: true`), следом приходит ролик «Итоги недели»: каждой новой возможности — своя сцена с показом на примере (экран чата из образца в описании изменения) и одной фразой о пользе; исправления и невидимые доработки в ролик не идут. Длина — `video.weekly_max_seconds` (120): чем больше, тем больше возможностей показано отдельно, остальные — списком.

- Полный список (0.14.0): следом приходят все завершённые изменения недели с пользой каждого, в разделах «Новое» и «Исправления и доработки». Способы по убыванию: виджет Telegram (страница прямо в сообщении, листается кнопками) → расширенное сообщение со сворачиваемыми разделами → обычный текст; не принят один — уходит следующий. На ноябрь 2026 Telegram виджеты обычным ботам не разрешает, поэтому приходит расширенное сообщение. `schedule.weekly_list` — с чего начинать: `widget`, `rich`, `text`; `off` — не присылать. Проба: `mcfly summary --weekly --list [--send]`.
- День и время — `schedule.weekly_day` (1 — понедельник … 7 — воскресенье) и `schedule.weekly_at`; `weekly_day: 0` — без недельной сводки.
- Проектам, поставленным до 0.13.0, нужно один раз выполнить `mcfly schedule install` — появится задание `weekly`.
- Вручную: `mcfly summary --weekly` (в терминал), `mcfly summary --weekly --send` (в Telegram), `mcfly video build --weekly` (ролик).

## Расписание и пропуски

По умолчанию прогоны в 00:00 и 04:00 до 180 минут, утренняя сводка в 08:00, недельная — в воскресенье в 19:00. Если Mac был выключен или спал, launchd запустит задание при пробуждении, runner увидит, что окно слота (30 минут) прошло, и запишет пропуск; сводка покажет его и подскажет ручной запуск. Прогон, наткнувшийся на лок другого прогона, записывается как «не запущен (шёл другой прогон)»; лок старше лимита прогона + 30 минут считается брошенным. Сон на время прогона блокирует `caffeinate`; ноутбук должен быть на зарядке.

## Безопасность

`mcfly init` добавляет в `.claude/settings.json` запреты: `git push --force`, `sudo`, `ssh`, `scp`, `launchctl`, `mcfly action` (действия запускает только владелец), чтение `mcfly/.env`, правка `mcfly/config.yaml`. Скилл процесса запрещает команде трогать прод-сервер и секреты, пропускать дельты спецификаций и ослаблять тесты. Токены живут только в `mcfly/.env` и в переменных окружения.

## Модели ролей

Лид работает на модели из `run.model` в `mcfly/config.yaml`; роли planner, architect, reviewer и analyst её наследуют. Роли с рутинной работой (developer, tester, devops, reporter, designer) закреплены за более дешёвой моделью полем `model:` в `agents/<роль>.md`; по умолчанию это `claude-sonnet-5-5`. Чтобы поменять раскладку, правьте эти поля в комплекте.

## Метрики

`mcfly metric` и технический хвост `mcfly summary` в терминале (в Telegram метрики с 0.9.0 не идут): число прогонов по статусам, оценка стоимости, задач закрыто, эскалаций, возвратов с ревью, падений тестов, изменений предложено и завершено.

## Устранение неполадок

- **Кнопки бота молчат, «💡 Предложения» не открываются**: нажатия и сообщения забирает только задание `answers` — выполните `mcfly schedule install`. С 0.11.0 `mcfly doctor` пишет «✗ бот не будет отвечать на кнопки и сообщения — нет задания answers».
- **Прогоны, кнопки бота и «запусти» с телефона молчат, пока экран погашен**: Mac засыпает, а спящий Mac задания не запускает. `mcfly doctor` (0.11.3) пишет «✗ Mac засыпает от сети через N мин» — выполните `sudo pmset -c sleep 0`; он же предупреждает о работе от аккумулятора и закрытой крышке.
- **В проекте ветка `master`, а не `main`**: команда создаёт ветки изменений от `main`. `mcfly init` и `mcfly doctor` (0.11.0) предупреждают об этом; переименуйте: `git branch -m master main`.
- **Нет chat_id**: `mcfly telegram pair`, затем отправьте боту сообщение и выполните `mcfly schedule install` — без chat_id задание опроса не ставится.
- **Сводка в Telegram**: сверху — что нужно от вас, под сообщением — кнопки ответа по умолчанию и одобрения. Нажатия и ответы текстом забирает задание `answers`: оно работает постоянно (launchd `KeepAlive`): цикл длинного опроса Telegram длится `schedule.answers_every_minutes` минут, после выхода сразу начинается новый, поэтому ответ приходит за секунды.
- **Запуск из Telegram**: напишите боту mcfly `запусти` — задание `answers` за секунды стартует прогон (если ничего не идёт) или ответит «⏳ Идёт прогон …». Если одобренной работы нет, а изменение ждёт одобрения, прогон не запускается: бот отвечает «⏸ Прогон не запущен» с кнопками одобрения (такой прогон только повторил бы «одобрите X» и потратил квоту); `запусти всё равно` запускает в любом случае. После одобрения кнопкой бот предлагает кнопку «▶️ Запустить прогон». Выключить запуск из Telegram: `run.telegram_start: false`.
- **Цепочка прогонов** (0.5.11): если после прогона осталась одобренная работа, прогон её продвинул (есть коммиты команды), а лимиты подписки позволяют — недельный ниже `run.chain_max_weekly` (0.7), пятичасовой ниже `run.chain_max_five_hour` (0.9), — сразу запускается следующий прогон, не больше `run.chain_max_runs` (8) за сутки. Доли лимитов runner берёт из событий `rate_limit_event` вывода Claude Code и пишет в `result.json` (`usage`); решение и причина — в поле `chain` и в строке «Дальше» итога. Выключить: `run.chain_max_weekly: 0`. Число изменений за прогон — см. «Сколько изменений за прогон» ниже.
- **Запас планов** (0.8.3): `ideas.plan_ahead` — сколько готовых планов команда держит на одобрении. По умолчанию 1: сделали изменение → спланировали одно следующее → ждём «Одобрить». При 3 после реализации команда дополняет очередь до трёх планов по самым старым взятым пунктам; владелец одобряет их пачкой, и прогоны идут цепочкой, пока есть одобренное и позволяют лимиты. Планы впрок строятся поверх ещё не сделанных изменений и запрашиваются с растущим `--priority`, чтобы порядок реализации совпал с порядком планов.
- **Мелкие изменения одобряются быстрее** (0.5.11): изменение до `escalation.small_change_max_tasks` (6) задач одобряется автоматически через `escalation.small_approval_deadline_hours` (4) часа, остальные — через `approval_deadline_hours` (24). Задание `answers` раз в цикл одобряет просроченные и, если лимиты позволяют и прогон не идёт, запускает прогон с сообщением в Telegram. Категории без ответа по умолчанию (prod) не одобряются никогда.
- **Отказы разрешений** агентам видны в `events.log` (⛔), `result.json` (`permission_denials`) и журнале `mcfly/progress.md`; в Telegram с 0.9.0 не показываются.
- **Идёт ли прогон**: `mcfly status` (первая строка) или файл `mcfly/.lock`; живая лента — `tail -f mcfly/runs/<id>/events.log`. По окончании прогона итог приходит в Telegram: статус, пересказ «Простыми словами» (для человека, не читающего код; его же утренняя сводка показывает блоками «🗣 Прогон … простыми словами»), до пяти пунктов «Нужно от вас» (списка «Сделано» с 0.9.0 нет) из отчёта репортёра, раздел «Решить» (текст открытых вопросов с ответом по умолчанию и сроком, выдержки изменений, ждущих одобрения), строка «Дальше» (что возьмёт следующий прогон или какого одобрения не хватает) и кнопки под сообщением.
- **Сколько изменений за прогон** (0.16.0): днём — `limits.max_changes_per_run`, ночью по расписанию — `limits.max_changes_night` (0 — как днём). Если задан список `limits.run_choices` (например `[1, 3, 5]`), на «запусти» бот спрашивает кнопками, сколько взять, и помечает прошлый выбор; «запусти 3» и `mcfly run --changes 3` задают число сразу. Прогон цепочки берёт столько же, сколько предыдущий.
- **Быстрый путь** (0.16.0): `ideas.fast_sizes` — размеры взятых пунктов (например `[S, M]`), план по которым одобряется сразу, если изменение не меняет то, что человек видит или нажимает, не относится к категории без ответа по умолчанию (prod) и укладывается в `limits.max_tasks_per_change`. Такой пункт проходит путь «Берём → план → работа» за один прогон; в итоге прогона он назван строкой «⚡ Без второго одобрения». Крупное и видимое по-прежнему ждёт кнопки «Одобрить» с образцами. Проверяет условия команда `mcfly approval request`, а не роли; ревьюер, заметив видимое изменение, возвращает план на одобрение (`mcfly approval hold`). По умолчанию выключено (`[]`).
- **Мелочи без одобрения** (0.17.0): `ideas.fast_edits: true` — быстрым путём идёт и мелкая правка существующего видимого по пункту S (в плане строка «Правка существующего: …» и образцы «было» и «стало»); `limits.followups_per_run` — сколько доделок к уже завершённой работе команда делает за прогон без «Берём» (`mcfly approval request <имя> --followup <завершённое изменение>`). Всё сделанное без одобрения стоит в итоге прогона блоком «⚡ Без вашего одобрения» с кнопками «↩ Вернуть». План, который команда вернула вам (`mcfly approval hold`), приходит вопросом с кнопками «Всё равно делать» и «Закрыть без работы». По умолчанию выключено.
- **Образцы картинками** (0.19.0): кнопка «👀 Как будет выглядеть» присылает картинки образцов альбомом (светлая и тёмная тема), если дизайнер указал их строками `Картинка: <путь>` под образцом; без картинок — текстом, как раньше. Для сообщений бота — шаблон «чат Telegram»: `mcfly samples template` кладёт его в `design/samples/telegram-chat.html`.
- **Большой пункт частями** (0.18.8): взятый пункт, который делается несколькими изменениями, планируют по частям — `mcfly approval request <часть> --idea <Iн> --part`. После архивации части пункт снова взят, а не закрыт; после последней части команда закрывает его `mcfly ideas done <Iн> --change <часть>`.
- **Порядок очереди** (0.16.0): «очередь» в боте показывает, что команда делает и что планирует; «⬆ Вперёд» (или «вперёд I7», `mcfly approval first <имя>`, `mcfly ideas first <Iн>`) ставит задачу первой. Команда в прогоне порядок не меняет.
- **Прогон со статусом network**: нет доступа к API. Ответ `403 Request not allowed` значит, что запрос ушёл без VPN (неподдерживаемый регион); бывают и сетевые ошибки. Runner повторяет прогон каждые `run.network_retry_minutes` (10) минут до `run.network_retries` (6) раз в пределах `max_minutes` (повтор не запускается, если после паузы до конца `max_minutes` останется меньше `run.min_retry_minutes`, по умолчанию 30 минут: работу возьмёт следующий прогон) и, если доступ не появился, сразу пишет в Telegram, не дожидаясь сводки. Включите в VPN-клиенте автоподключение. Если его нет, а VPN зарегистрирован в macOS (виден в `scutil --nc list`), укажите его имя в `run.vpn_service`: runner проверит VPN перед прогоном и перед каждым повтором, при необходимости запустит `scutil --nc start` и подождёт до минуты; переподключение видно в `events.log` и заметке прогона, `mcfly doctor` проверяет, что сервис найден. Прогоны со статусом error тоже сообщаются в Telegram сразу.
- **Прогон висел на повторах API**: без доступа к API (VPN упал, Mac уснул посреди запроса) `claude -p` сам повторяет запрос — события `api_retry` в `stdout.log` — и раньше висел до `max_minutes`, получая статус timeout и занимая следующий слот. С 0.5.8 сторож прерывает такую попытку, если после серии `api_retry` без ответа модели вывода нет `run.api_stall_minutes` (10) минут или серия длится `run.api_retry_span_minutes` (20) минут; попытка считается сетевой (network) и повторяется как обычно. В `events.log` — строка «⛔ прерван: нет доступа к API …».
- **Сообщение в Telegram не дошло** (нет связи, `UND_ERR_CONNECT_TIMEOUT`): итог прогона, тревога и ответ на сообщение ставятся в очередь `mcfly/logs/pending-notices.jsonl`; задание `answers` досылает её после первого удачного опроса с пометкой «🕓 Не дошло вовремя (время)». Сообщения старше 48 часов не досылаются. Утренняя сводка, не ушедшая из-за связи, досылается целиком (с роликом) тем же заданием в тот же день до 18:00 (0.18.3); позже — её период войдёт в следующую сводку. Нажатие кнопки, сделанное, пока связи не было, Telegram может не доставить вовсе — нажмите ещё раз или выполните `mcfly approval set`.
- **Прогон со статусом quota**: достигнут лимит подписки; следующий прогон пройдёт по расписанию, либо запустите днём `mcfly run --mode day`. Недельный лимит («weekly limit») роняет все прогоны за секунды до сброса: следите за расходом дневных сессий в тот же аккаунт.
- **«Background tasks still running after 600s; terminating» в stdout.log**: так CLI до 0.3.0 убивал фоновых субагентов после ухода лида в ожидание; с 0.3.0 фон в прогоне отключён. В `result.json` поле `subagents.background` должно быть 0.
- **Пропущенные прогоны**: Mac спал; проверьте зарядку и `mcfly schedule status`.
- **Бот mcfly молчит после `mcfly schedule install`**: выполните `mcfly schedule status` — строка «✗ … answers … НЕ загружено» значит, что задание опроса не работает; повторите `mcfly schedule install`. С 0.8.1 install сам ждёт до 30 с, пока launchd отпустит прежнее задание (процесс опроса уходит не мгновенно), повторяет загрузку до 5 раз и при неудаче пишет строку ✗ с причиной. До 0.8.1 загрузка шла сразу за выгрузкой и падала с ошибкой 5 «Input/output error» — answers пропадал до повторного install (07.11).
- **VPN**: прогоны не зависят от VPN, но задачи с внешними системами могут; проектируйте тесты через записанные ответы.
- **401 OAuth access token is invalid при прогоне**: у отдельного CLI устарел токен подписки. Войдите заново в терминале (`claude`, затем `/login`) или получите долгоживущий токен `claude setup-token` и положите его в `mcfly/.env` как `CLAUDE_CODE_OAUTH_TOKEN`. Проверка: `mcfly doctor --probe`.
- **Агент `mcfly:lead` не найден**: проверьте `claude plugin validate ~/mcfly` и значение `run.lead_agent` в `mcfly/config.yaml`.
