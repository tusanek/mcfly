# Долги и отложенное

Отложено с доработки 0.11.0 (2026-11-15, находки запуска нового проекта):
- «Нужно от человека» не видит, что уже сделано: в 0.11.0 — только правило репортёру (проверить; нельзя проверить — «если ещё не сделано: …»). Кнопка «✅ Уже сделано» под пунктом, после которой он пропадает из сводки и «Статуса», не сделана: нужен устойчивый номер пункта между отчётами.
- Галочка в `mcfly/goals.md` ставится по совпадению названия предложения с текстом пункта; если аналитик при переносе бэклога переписал название, пункт не отметится. Надёжнее хранить в предложении ссылку на строку целей при переносе.
- Обращение на «вы» — правило для агентов; кодом не проверяется. Если владелец выберет «ты», менять придётся и служебные строки бота (их сотни) — сделать настройкой.
- Находки для mcfly: нет команды «/findings» в меню «/» (ревизия меню не менялась, чтобы не рассылать объявление); общий ящик — локальный файл, отправка в задачи GitHub не сделана; скрываются только ключи и токены известного вида — подробности проекта убирает правило для агентов и сам владелец при одобрении.
- Требование раздела «Как это будет выглядеть» в `mcfly approval request` проверяет только наличие раздела, а не то, вызывался ли дизайнер.

Отложено с ревью 0.7.6–0.7.12 (2026-11-01):
- «Отложено» считается в двух местах по-разному: сводка (`pausedChanges`) — только с открытыми задачами, «Статус» (`changeLine`) и авто-передача — любое отложенное; у закрытого отложенного изменения — лишняя строка «⏸ … не брать». Нужна одна функция для всех.
- `ideaSettled`: отклонённый пункт (`rejected`/`discuss` без изменения) не закрывает «Кнопки одобрения: I…» — редкий случай, теста нет.
- `ideasCovered` вырезает «Решить по предложениям» и при выключенном `ideas.enabled`, а строка из состояния тогда не печатается — просьба пропадает (в рабочем проекте владельца предложения включены).
- Идущий прогон, начатый до начала периода сводки, не показывается строкой «▶️ … идёт» (`cur.since > since`).
- Запахи: циклический импорт `runner.js → summary.js → runner.js` (`currentRun`); `commitMeta` — замыкание в `cli.js`; поле `paused_at` пишется, но не читается; `eventKV` экспортируется без внешних вызовов.

Найдено 2026-10-24 (0.6.3):
- Один `.openspec.yaml` с ошибкой YAML (двоеточие в непрокавыченном `goal`) останавливает применение всех сообщений Telegram («⚠️ Не удалось применить сообщения … Nested mappings…») и обзоры: `listChanges` должен пропускать такое изменение с предупреждением, а `mcfly doctor` — показывать его ✗ (`openspec validate` этот файл не проверяет).

Отложено с ревью 0.7.1–0.7.4 (2026-10-27):
- «Можно сделать кнопкой»: `currentRun` читается до проверок `offer` (до 10 с); если прогон стартует в это время, кнопка выката может остаться в сообщении — бот всё равно не запустит её во время прогона (мелкая гонка).
- `changeTitle` читает `ideas.yaml` на каждое изменение; «Сводка» показывает у изменения только номер и название, без второй строки «имя · дальше» (как в «Статусе») — достаточно для утренней сводки.

Найдено 2026-10-25 (0.6.3):
- Задание `answers` загружает `mcfly/config.yaml` один раз при старте цикла (`cli.js`, `cfg` передаётся в `pollAnswers` на `answers_every_minutes`) и проверяет подтверждение действий по этой копии. После правки раздела `actions` и `mcfly action trust` бот до конца цикла (до 10 минут) отвечает на «🛠 Действия» ложным «⚠️ Раздел actions … не подтверждён», хотя `mcfly doctor` уже показывает ✓ (25.10: кнопка `backup` добавлена в 10:40, trust в 10:43, кнопки заработали только после перезапуска цикла в 10:46). Правка скриптов так не проявляется — файлы читаются при каждой проверке. Исправить: перечитывать config (хотя бы раздел `actions`) при каждой проверке `isTrusted`/обработке кнопки или при изменении mtime файла; тест — правка `actions` и trust посреди цикла опроса.

Отложено с ревью 0.5.3–0.5.5 (2026-10-02):

- Перехват брошенной блокировки опроса «прочитал — удалил» неатомарен; спасает проверка `ownsPullLock` после getUpdates — перейти на `rename`.

- ~~Подтверждения (acks) отправляются после сохранения offset: при обрыве сети теряются молча.~~ С 0.5.8 — очередь недошедших сообщений.
- «Нужно от вас» не сверяется со списком вопросов (пункт «ответить на Q3» дублирует вопрос); при обрыве отправки на второй части сводки первая завтра придёт повторно.
- Запахи: дубль проверки «прогон старой версии» в cli.js и pull.js; `pullAnswers` с 13 параметрами; блокировку опроса вынести в отдельный модуль.

Отложено по ревью 2026-09-29 (причина — в скобках):
- `/mcfly:run` в интерактивной сессии идёт через `--dry-run`: ответы из Telegram не забираются, просроченное не закрывается, прогон не записывается (нужен режим подготовки без запуска claude — отдельное решение);
- тесты CLI вызывают установленные `claude` и `openspec` (заглушки в PATH; на результат пока не влияет);
- пропущенный прогон коммитит служебные файлы, даже если идёт другой прогон (редкий случай: пробуждение Mac во время ручного прогона; после 0.3.0 коммитятся только служебные пути);
- deny-правило `git push --force*` не ловит `git push origin main --force` (команда не пушит; синтаксис шаблонов прав уточнить);
- runner делает слишком много — лок, окно, Telegram, поток событий, git, авто-сводка (разделить при следующей доработке);
- worktree команды в detached HEAD (обрыв посреди rebase) считается чужим и выпадает из «незакоммиченной работы» (редкий случай);
- тесты прогона вызывают установленный `openspec validate` (заглушка в PATH вместе с тестами CLI);
- deny-правила на `.env` закрывают инструменты Read, Edit и Write, но не `cat .env` через Bash и не `.env.local` (синтаксис правил Bash уточнить вместе с правилом force push).

Сводка роликом (0.12.0), отложено:
- `mcfly video setup` на чистом Mac (создание окружения Python и скачивание модели голоса) написан, но проверен только путь с готовым окружением;
- образцы не привязаны к прогону: показываются после всех сцен «Что сделано», а не рядом со своей;
- ударения ставит синтезатор сам и иногда ошибается — правится словарём `video.pronounce`;
- недельная сводка (0.13.0): период — всегда семь дней назад от отправки; если Mac был выключен в назначенный час, сводка за эту неделю не приходит (спящий Mac launchd догоняет сам);
- виджет недели (0.14.0) сделан по документации и проверен только в браузере: Telegram на 16.11.2026 отказывает обычным ботам (`INPUT_MEDIA_WIDGET_NOT_ALLOWED`); когда откроет — проверить вид в приложениях и, возможно, сделать `rich` способом по умолчанию, чтобы не слать заведомо неудачный запрос;
- виджет статичный: запросов к боту нет, отметить или одобрить что-то из него нельзя;
- недельный ролик: «исправление или возможность» определяется по названию изменения и наличию образца — грубо; надёжнее пометка в самом изменении;
- показ на примере — один экран чата (первый образец); связки «сообщение владельца → ответ бота» из двух образцов нет;
- недельная сводка без кнопок: решения по вопросам и планам — в утренней сводке и «Статусе»;
- ролик собирается в том же процессе, что отправляет сводку: при `mcfly summary --send` из терминала команда ждёт сборку.

Ролик с режиссёром (0.15.0), отложено:

- запасные сцены недельного ролика по-прежнему перечень возможностей одинаковыми сценами;
- запасные сцены утреннего ролика берут три последних прогона, а не список `done` по приоритету (0.15.2 дал его только режиссёру);

- команда `mcfly video build --director off` не покрыта тестом вывода: запускает настоящую сборку.
