# Передача смены между днём и ночью — дизайн

Дата: 2026-09-30. Статус: одобрен владельцем 2026-10-01, реализован в 0.5.0. Целевая версия комплекта: 0.5.0.

## Зачем

Днём владелец работает с Claude над задачами проекта, ночью команда mcfly продолжает без него. Сейчас передача держится на ручных действиях: заметка в `mcfly/answers.md`, бриф `next_chat_prompt.md`, а лид сам выбирает работу по приоритетам. Дневная работа идёт в ветках сессий мимо `tasks.md` изменений, и команда о ней не знает.

Цель: день заканчивается в любой момент, и ночь продолжает с того же места по явному плану. Утром ночь так же передаёт работу дню. Сводка в Telegram остаётся.

Критерии успеха:
- после «сдай смену» ночной лид начинает с задачи, на которой остановился день, в той же ветке `change/*`;
- если смену не сдали, ночь идёт по авто-передаче и не повторяет и не ломает несданную дневную работу;
- утром «прими смену» за один шаг даёт план дня, сверенный с фактами;
- сводка 10:30 приходит в Telegram, как сейчас, и содержит предложение на день.

## Решения владельца (2026-09-30)

1. Передача в обе стороны: вечером день → ночь, утром ночь → день.
2. Вечером явная команда «сдай смену». Если её не было, runner перед прогоном сам собирает авто-передачу.
3. Днём задачи изменения делаются в ветке сессии, ответвлённой от `change/<имя>`. При сдаче смены она вливается в `change/<имя>` через `--ff-only`.
4. Утром — «прими смену» по файлу, который оставила ночь. Для рабочих дней передача заменяет бриф `next_chat_prompt.md`.
5. «Сдай смену» — лёгкая ежедневная команда без ревью. Полный wrap-up — только для особых случаев: менялся комплект, были важные решения.
6. Передача поручает ночи работу только в рамках одобренного: порядок изменений и задач, точку продолжения, что не трогать, заметки. Одобрения и приоритеты меняются только через `mcfly approval set`.
7. Строить в комплекте mcfly (вариант 1 из трёх), с отдельными файлами смен.
8. Сводка в Telegram остаётся.

## Файлы смен

Каталог `mcfly/shifts/`, один файл на передачу. Файлы коммитятся и не переписываются.

- `ГГГГММДД-ЧЧММ-day.md` — вечерняя сдача. Пишет дневная сессия (`источник: человек`) или runner (`источник: авто`).
- `ГГГГММДД-ЧЧММ-night.md` — утренняя передача. Пишет репортёр последнего слота ночи (`источник: команда`) или runner, если прогон не дошёл до отчёта (`источник: авто`).

Последняя передача каждого вида — самый новый файл по имени.

Формат одинаковый в обе стороны: markdown с обязательными заголовками.

```
# Смена: день → ночь, 2026-10-01 18:30 (источник: человек)
## Изменения
### llm-adaptation — ветка change/llm-adaptation @ 1a2b3c4, задач 4/10
- Где остановились: 2.3 наполовину — парсер готов, тест классификатора красный (намеренно)
- Дальше: 2.3 → 2.4 → 3.1
- Не трогать: …
## Порядок
1. llm-adaptation
2. page-map-seed
## Нужны решения человека
- нет
## Заметки
- …
```

В ночной передаче шапка «Смена: ночь → день» со ссылками на прогоны ночи (`runs/<id>`), а раздел «Порядок» называется «Предложение на день». Обязательные заголовки: `# Смена:`, `## Изменения`, `## Порядок` или `## Предложение на день`, `## Нужны решения человека`, `## Заметки`.

## Дневная сторона

Навыки плагина `/mcfly:take-shift` («прими смену») и `/mcfly:hand-shift` («сдай смену») думают и пишут текст. CLI `mcfly shift` выполняет проверяемые действия с git.

### «Прими смену» (утро)

1. Если есть `mcfly/.lock`, идёт прогон: сообщить и ничего не менять.
2. Прочитать последний `-night.md` и сверить с фактами: ветки `change/*`, `runs/<id>/result.json`. Расхождения назвать.
3. Предложить план дня: что делаем вместе, что оставляем ночи, какие решения нужны от владельца.
4. Для работы над изменением: `mcfly shift start <имя>` переводит worktree сессии на новую ветку `shift/<имя>-ГГГГММДД-ЧЧММ` от `change/<имя>`. Если в worktree сессии есть незакоммиченное, имя не указано или изменения нет (ни ветки `change/<имя>`, ни `openspec/changes/<имя>`) — отказ. По префиксу `shift/` runner находит дневную работу. Работа вне изменений (исследования, документы, комплект) идёт от main, как сейчас.

### «Сдай смену» (вечер)

1. Есть лок — отказ.
2. Отметить `[x]` в `tasks.md` в ветке сессии и закоммитить работу вместе с отметками. Красный тест — коммитом `wip(<имя>): …`. После merge сессия в detached HEAD — в ней больше не коммитят.
3. `mcfly shift merge`: влить ветку сессии `shift/<имя>-…` в `change/<имя>` через `git -C <worktree команды> merge --ff-only <ветка сессии>`.
   - `change/<имя>` ушла вперёд — сначала влить её в ветку сессии, затем fast-forward.
   - Конфликт — стоп и вопрос владельцу; без rebase и `--force`.
   - В worktree команды есть незакоммиченное — стоп и вопрос владельцу.
   - Работа вне изменений вливается в main, как сейчас.
   - После влития ветка `shift/…` удаляется: её коммиты уже в `change/<имя>`.
4. Приоритеты и одобрения менять, только если владелец так сказал, — через `mcfly approval set`.
5. Навык составляет текст. `mcfly shift write`:
   - проверяет обязательные заголовки; при нехватке не записывает и называет, чего не хватает;
   - предупреждает, если передача упоминает неодобренное или несуществующее изменение, но записывает;
   - кладёт файл в `mcfly/shifts/`, коммитит только его в main (как `approval set` в 0.4.0);
   - добавляет строку в `mcfly/progress.md`;
   - отправляет в Telegram строку вида «Смена сдана 18:30: ночью llm-adaptation с 2.3, затем page-map-seed; решений не ждёт».
6. Показать владельцу итог: что ночь будет делать и в каком порядке.

Сессия сама напоминает о сдаче смены. Время привязано к квоте: если текущее пятичасовое окно истекает до 02:00, заканчивать до его сброса.

## Ночная сторона

### Перед прогоном (runner)

- Последний `-day.md` новее последнего `-night.md` — день сдал смену, прогон работает по ней.
- Иначе `mcfly shift auto` собирает авто-передачу (`источник: авто`), runner коммитит её как служебный файл. Содержание:
  - по каждому одобренному изменению: sha `change/*`, прогресс `tasks.md` из ветки, незакоммиченное в worktree команды;
  - несданная дневная работа: ветки `shift/<имя>-…` с коммитами, которых нет в `change/<имя>`, и их worktree с незакоммиченным. Пометка «не сдано днём — не трогать, не повторять»;
  - порядок — по приоритетам одобрений.
- `-night.md` пишется только в последнем слоте ночи, поэтому прогон 06:00 видит ту же дневную передачу, что и 02:00.

### Лид

- Передача — первый блок контекста с правилом «действуй по передаче в рамках одобренного».
- При конфликте побеждают одобрения и спецификации. Неодобренное, упомянутое в передаче, не трогать, записать в «Нужны решения человека».
- Файл с нарушенным форматом, положенный в обход `shift write`, лид получает как есть с пометкой «формат нарушен».
- Шаг 0 («подхватить незавершённую работу») начинается с раздела «Где остановились».

### Конец ночи

- Последний слот ночи — последний из `schedule.slots`. Репортёр этого прогона вместе с `summary.md` пишет `-night.md`: что сделано за ночь по изменениям, где остановились, какие решения нужны, предложение на день.
- Если этот прогон не дошёл до отчёта (`quota`, `missed`, ошибка), runner собирает `-night.md` сам (`источник: авто`) по коммитам и веткам, как сейчас авто-сводку; ссылки — прогоны ночи после действующей дневной передачи. Блок передачи — только в промпте ночного прогона, в контексте хука SessionStart дневных сессий его нет.

### Сводка 10:30

Как сейчас, плюс блок «Предложение на день» из последнего `-night.md` — по две-три строки на изменение. Если ночь шла по авто-передаче: «смену не сдали — ночь шла по авто-передаче».

Ручные прогоны днём (`mcfly run`) передачи не пишут, но читают последний `-day.md`, если он есть.

## Тесты

Node, как сейчас, без сети; git во временных репозиториях; Telegram — заглушка.

- Выбор последней передачи и правило «день новее ночи», в том числе прогон 06:00 после 02:00.
- Авто-передача: прогресс из веток, грязные worktree команды, несданные ветки сессий.
- `shift merge`: fast-forward; влить `change/*` при расхождении; отказ при локе, грязном worktree команды и конфликте.
- `shift write`: проверка заголовков, коммит только своего файла, предупреждение о неодобренном, строка в Telegram.
- `shift start`: ветка `shift/<имя>-…` от `change/<имя>`, отказ при грязном worktree сессии.
- Контекст лида: передача первым блоком, пометка о нарушенном формате.
- `-night.md` в последнем слоте; авто-версия при `quota`.
- Сводка с блоком «Предложение на день» и строкой об авто-передаче.

Навыки проверяются глазами и одним ручным днём на emmett-brown.
