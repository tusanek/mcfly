# mcfly v0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Собрать переиспользуемый комплект «ИИ-команды разработки» mcfly: плагин Claude Code с ролями-субагентами и скиллами процесса, Node-CLI для ночных прогонов на Mac (launchd), двусторонний Telegram (утренняя сводка, вопросы, одобрения), адаптации OpenSpec (флаг одобрения), метрики.

**Architecture:** Репозиторий `~/mcfly` одновременно является плагином Claude Code (`.claude-plugin/plugin.json`, `agents/`, `skills/`, `commands/`, `hooks/`) и npm-пакетом с CLI `mcfly` (`bin/mcfly`, `src/*.js`, ESM, Node ≥ 20, единственная зависимость `yaml`). Состояние проекта живёт в каталоге `mcfly/` целевого проекта (config.yaml, progress.md, questions.yaml, answers.md, metrics.jsonl, runs/). Прогон = `claude -p --plugin-dir ~/mcfly --agent mcfly:lead "<промпт>"`, запускаемый runner'ом с проверкой окна, `caffeinate`, лимитом времени и разбором JSON-результата. OpenSpec (`openspec` CLI) — слой спецификаций; mcfly добавляет блок `mcfly.approval` в `.openspec.yaml` изменения. Все дочерние процессы запускаются через `spawn`/`spawnSync` с массивом аргументов, без оболочки.

**Tech Stack:** Node 24 (ESM, `node:test`, `node:util.parseArgs`), пакет `yaml`, Claude Code CLI 2.1.x, OpenSpec 1.13, launchd, Telegram Bot API (fetch).

**Решения из SHARED-UNDERSTANDING.md (раздел 2):** роли (lead, analyst, architect, planner, developer, tester, reviewer, devops, designer, reporter); прогоны 00:00 и 04:00 до 3 часов; сводка 08:00; пропущенный прогон не догоняем; эскалации по пяти категориям с ответом по умолчанию и сроком 24 ч (prod — никогда по умолчанию); молчание 24 ч = одобрение изменения (кроме prod); метрики с первого дня; agent teams не используются.

## Приложение А: тексты агентов и скиллов

Роли (frontmatter: `name`, `description`, при необходимости `tools`, `isolation: worktree` у developer):

- **lead** — координирует прогон по промпту runner'а; вызывает роли через Agent по имени `mcfly:<роль>` с полным контекстом; следит за дедлайном (за 15 минут — завершение); эскалирует через `mcfly question add` и продолжает по умолчанию (кроме prod); в конце — отчёт репортёра, строки в progress.md, чистый `git status`, удалённые worktree.
- **analyst** (tools: Read, Grep, Glob, Bash, WebFetch, WebSearch) — факты со ссылками на файлы, требования в формате OpenSpec (SHALL/MUST + Scenario WHEN/THEN), неясности с ответом по умолчанию и категорией; ничего не меняет.
- **architect** (tools: Read, Grep, Glob, Bash, Write, Edit) — design.md и ADR в `docs/adr/NNNN-<тема>.md`; глубокие модули; новая зависимость = категория deps; задачи по 2–5 минут, проверяемые тестом; код не пишет.
- **planner** — `openspec new change <имя> --goal`, артефакты proposal/дельты/design/tasks (≤ лимита задач), `openspec validate <имя> --strict`, `mcfly approval request <имя> --category spec|prod`; для одобренных — план прогона с непересекающимися файлами.
- **developer** (isolation: worktree) — одна задача: красный тест → зелёный → рефакторинг → коммит `feat(<изменение>): …` → `[x]` в tasks.md; не выходит за границы файлов; не меняет спецификации; два неудачных подхода → stuck; тесты не ослабляет.
- **tester** — чек-лист из сценариев дельт; недостающие интеграционные тесты; полный набор тестов; отчёт «сценарий → тест → результат», дефекты с воспроизведением, вердикт; `mcfly metric add --key tests_failed --value N`; реализацию не правит.
- **reviewer** (tools: Read, Grep, Glob, Bash) — соответствие спецификации, стандарты, чек-лист безопасности (секреты, инъекции, внешние данные, файловая система и git, зависимости); замечания с файлом/строкой/серьёзностью; вердикт; при возврате `mcfly metric add --key review_rejections`.
- **devops** — слияние в main без конфликтов, тесты на main, удаление worktree и веток; архивация `openspec archive <имя> --yes` строго по одному + `mcfly metric add --key changes_archived --change <имя>`; Dockerfile/compose/скрипты, которые человек выполняет сам; всё про прод — категория prod и остановка.
- **designer** — информационная архитектура и оформление интерфейсов и сайта документации; `docs/design/<тема>.md`; код не пишет.
- **reporter** — `<каталог прогона>/summary.md` с разделами «Сделано / В работе / Блокеры и вопросы / Метрики прогона / План на следующий прогон», 1–3 строки в progress.md, ненулевые метрики (`tasks_done` и др.); коротко и конкретно.

Скиллы:

- **mcfly-process** — цикл прогона (5 шагов), артефакты, ворота качества (TDD, `validate --strict`, ревью, conventional commits, чистое дерево), эскалации (5 категорий, команда, поведение по умолчанию, prod — остановка, одобрения и 24 часа), лимиты, запрещённое, определение готовности изменения.
- **mcfly-openspec** — структура каталогов, команды CLI без интерактива, формат дельт (ADDED/MODIFIED/REMOVED, Requirement, Scenario), блок одобрения `mcfly:` в `.openspec.yaml`, параллельная работа (один владелец, ветки `change/<имя>`, последовательная архивация), правила (≤10 задач, дельты обязательны, `--skip-specs` запрещён, `validate --strict` перед одобрением и архивацией).
