# Новый проект с mcfly за 30 минут

0. Установите инструменты: Claude Code CLI с подпиской, `npm install -g @fission-ai/openspec@latest`, комплект `git clone https://github.com/tusanek/mcfly.git ~/mcfly && cd ~/mcfly && npm install && npm link`.
1. В каталоге проекта: `git init -b main` (если ещё нет; команде нужна ветка `main` — старую `master` переименуйте: `git branch -m master main`) и `mcfly init --name <проект> [--with-tracker]`. Появятся `mcfly/`, правила в `.claude/settings.json`, раздел в CLAUDE.md, `openspec/` с командами `/opsx:*`.
2. Создайте бота в BotFather, скопируйте токен: `cp mcfly/.env.example mcfly/.env` и впишите `MCFLY_TELEGRAM_TOKEN=…`.
3. `mcfly telegram pair`, затем отправьте боту любое сообщение — chat_id сохранится в `mcfly/config.yaml`.
3а. `mcfly schedule install` — сразу: без него бот не отвечает на кнопки и сообщения (их забирает задание `answers`). Заодно ставятся ночные прогоны и сводка.
4. `mcfly doctor` — все пункты должны быть ✓.
5. Первые спецификации. Либо дайте команде сформулировать их самой (первый прогон создаст изменения и запросит одобрение), либо создайте стартовое изменение вручную: `openspec new change bootstrap --goal "…"`, заполните proposal, дельты specs, design и tasks (в интерактивной сессии удобно `/opsx:propose`), проверьте `openspec validate bootstrap --strict` и одобрите: `mcfly approval set bootstrap approved --note "стартовое"`.
6. Пробный прогон: `mcfly run --mode day --dry-run` покажет команду и сохранит промпт в `mcfly/logs/dry-run-<id>.prompt.md` (вне git); затем `mcfly run --mode day` запустит команду по-настоящему.
7. Расписание уже стоит с шага 3а (прогоны 00:00 и 04:00, сводка 08:00; меняется в `mcfly/config.yaml`, после правки повторите `mcfly schedule install`). Ноутбук на ночь оставьте на зарядке.
8. Утром: читайте сводку в Telegram, отвечайте `Q1: …`, `approve <имя>`, `reject <имя> причина`. Ответы попадут в `mcfly/answers.md` сразу по приходу: их применяет задание `answers` (вручную — `mcfly answers --once`). В любой момент: «где мы» — обзор проекта, «последний прогон», «статистика», «помощь» — все команды; кнопки — внизу чата и в меню «/».
8а. Описание продукта (советуем): замените подсказку в `mcfly/product.md` своим текстом — что это, для кого, какую боль снимает, правила, которые нельзя нарушать — и закоммитьте. Команда получит его в начале каждого прогона, начнёт показывать образцы до одобрения плана (кнопка «👀 Как будет выглядеть») и проходить готовое глазами пользователя. Неудобное пишите боту: «неудобно: …».
9. Цели (по желанию): создайте `mcfly/goals.md` — разделы «## Цель», «## Ближайшая веха» и чек-лист «- [x] сделано» / «- [ ] осталось» — и закоммитьте; бот по команде «цели» покажет «сделано N из M». Пункт вашего бэклога, который сделала команда, mcfly отметит сам.
10. Бэклог (по желанию): в `mcfly/config.yaml` укажите `ideas.backlog` — где лежит ваш бэклог; команда перенесёт его в «💡 Предложения», и следующую работу вы выберете кнопкой «Берём».
11. Что-то не так в самом mcfly (а не в проекте): напишите боту «mcfly: что не так» — запись уйдёт в общий ящик доработки `~/mcfly-inbox.md`. То, что заметила команда, придёт вам кнопкой «📮 Находки для mcfly» — решаете «Передать» или «Не надо».
